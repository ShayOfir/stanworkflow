📊 infer_contrasts Integration Map

How infer_contrasts bridges the Bayesian workflow, connecting data extraction, posterior inference, and statistical contrasts.

Call Chain: User → Pipeline

1. User Entry Point
regimen() (regimen.R)
Orchestrator: wraps data, contrasts, sampler params, and wflow lifecycle
2. Workflow Controller
infer.regimen() → run_inference() (regimen.R → wflow.R)
Passes control: fitted model, contrast specs, data to wflow
3. The Bridge Function
run_inference.wflow() → infer_contrasts() (wflow.R → infer.R:1317)
Centrality: 7 edges — Critical hub between:
  • Posterior draws (from wf$post_fit)
  • Data specification (features, grouping)
  • Contrast definitions (categorical, continuous, 2-way)
4. Internal Extraction Pipeline
infer_contrasts() internally routes through:
When Path Purpose
Setup .resolve_spec() Normalize outcome_spec (yrep, marginal, extensive, intensive)
Hurdle Expand to 3 sub-contrasts If os_hurdle(), run all 3 margins in one pass
Extract .get_yrep_draws() Pull posterior predictive or GQ from draws
Method descriptive or counterfactual Observed grouping vs. grid sweep across contrast_var
Compute .compute_one_contrast() Hi/lo split, difference, summarize
2-way .compute_two_way_contrast() 4 scenarios: both, first only, second only, neither
Counterfactual .compute_counterfactual_contrast() Grid-point-wise scenario or continuous contrast curve
5. Return & Persist
inference object → wf$inference[[name]] → Saved to disk (regimen.R)
Result: list of posterior draws, summary stats, scenarios, credible intervals

Data Flow Through infer_contrasts

INPUT: model : stanmodel (fitted posterior draws) contrasts : contrast or list of contrast objects data : tibble (features for grouping/differencing) draws_method : "descriptive" or "counterfactual" gq_steps : integer (grid resolution) PROCESSING: 1. .resolve_spec() → determine GQ variable per outcome_spec 2. If hurdle: expand into 3 sub-contrasts (marginal, extensive, intensive) 3. Pool needed variables across all contrasts 4. .get_yrep_draws() → extract draws 5. For each contrast: - Apply contrast split (hi/lo or categorical levels) - Summarize per draw and grouping cell - Compute contrast (hi - lo) - Classify scenarios (if 2-way) - Aggregate to posterior summaries 6. Assign to inference results OUTPUT: Per contrast type: descriptive + 1-way: $summary : mean/interval/P_positive per grouping cell $posterior : full per-draw posterior descriptive + 2-way: $scenario_probs : 4 scenarios per grouping cell $scenario_draws : per-draw classifications counterfactual: $grid_summary : contrast vs grid point $grid_posterior : full draws per point
✓ Why infer_contrasts is the critical hub:
  • Specification ↔ Extraction: Translates contrast objects into data extraction logic
  • Extraction ↔ Computation: Bridges posterior GQ to contrast-specific computation
  • Three inference paths unified: 1-way, 2-way, counterfactual into single interface
  • Final integration: Where user-specified contrasts meet fitted posterior draws
